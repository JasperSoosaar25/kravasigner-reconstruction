# Ideas for community contributions

These are starting points for discussion, not promised features or a release schedule. Search existing issues before proposing one, and use the feature-request form for a larger change.

| Possible improvement | A useful acceptance target |
| --- | --- |
| Better repository search and filtering | Find an app quickly, with readable empty/error states and no loss of repository data |
| Download queue controls | Cancel/retry has clear state and does not leave broken files or duplicate jobs |
| Accessibility improvements | VoiceOver names controls correctly; large text stays readable |
| Clearer error messages | Explain actionable causes without exposing secrets |
| More appearance choices | Preferences persist and work in light/dark mode without hiding important status |
| Translation improvements | Strings are reviewed in context and compile from the editable catalog |
| Tests around services and storage | Use invented data and check user-visible behavior |

Signing, installation and data-model changes need extra care and real-device or migration validation. New community behavior should be documented separately from recovered original behavior.
